# Course Conventions

## Naming

- Python packages and modules: `snake_case`.
- Configuration files: descriptive `snake_case`; avoid numbering except where lesson order is part of the participant interface.
- Run IDs: generated by the runner; never encode results in a filename.
- Distributed ranks: zero-padded in artifacts, for example `rank-000.json.gz`.
- Exercise and solution files use the same basename under their respective directories.

## Python

- Python 3.12 is canonical because the pinned image provides Python 3.12 packages.
- `uv.lock` pins course-owned Python dependencies.
- Do not add `torch`, CUDA, NCCL, or network-stack packages to `pyproject.toml`.
- Format and lint with Ruff once code volume justifies it; avoid formatting imported legacy material in its history-preserving copy commit.
- Public interfaces require type annotations and concise docstrings for non-obvious contracts.

## Exercises

- Each exercise states its outcome, prerequisite, expected runtime, and required resources.
- Day 1 keeps the training loop explicit.
- Gaps are deliberate and bounded; reference solutions must be executable.
- Resource-dependent exercises provide a small local path or recorded metrics/traces.

## Notebooks

- Prefer text-based Jupytext sources for review and Git blame once the notebook workflow is introduced.
- Participant-facing `.ipynb` files must execute from a clean kernel.
- Outputs are cleared from source unless they are small, intentional teaching evidence.
- Important implementation code belongs in importable modules, not only in notebook cells.

## Slides

- Slide code refers to tested files or commands.
- Do not maintain a second implementation in a slide.
- Figures retain source and licence information.
- Generated slide output is not committed.

## Git migration

Git stores snapshots and infers moves and copies from similarity.

- Use a dedicated `git mv` commit for one-to-one relocations when the old path can disappear.
- Otherwise make an exact copy and commit it without edits so the old course remains operational.
- Adapt content only in later commits.
- Verify copies with `git log --follow -C --find-copies-harder -- <path>` and `git blame -C -C <path>`.
- Put original source paths in the copy/move commit message.
- Preserve copyright, citation, licence, and upstream-version notices for third-party material; Git history does not replace them.

## Runtime artifacts

The following remain outside Git:

- downloaded or tokenized datasets;
- model checkpoints;
- profiler and Nsight traces;
- run directories and generated reports;
- notebook checkpoints and generated slide output.

Small deterministic fixtures and reference summaries may be committed when they directly support a behavioral check or offline exercise.
